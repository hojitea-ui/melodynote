# AI 기능 PRD

## 1. 기능 정의
- **기능 이름: 멜로디노트**
- **한 줄 설명: 녹음한 멜로디를 오선지 위의 음으로 변환한다**

## 2. 사용자와 사용 맥락
- **주 사용자: 작곡가 및 연주자**
- **현재 불편: 모티브를 음성으로 녹음하면, 이를 오선지에 박자와 음으로 다시 옮겨 그리는 과정을 한 번 더 거쳐야 한다**

| 항목 | 내용 | 근거 |
|---|---|---|
| 대상 사용자 | 작곡가 및 연주자 | 가정 |
| 필요한 시점 | 모티브가 떠올랐을 때 즉흥적으로 (곡 아이디어를 다른 사람에게 설명할 때도) | 가정 |
| 사용 중인 기기와 도구 | 폰 브라우저에서 바로 녹음, 이후 작업은 노트북이나 악기 앞 | 가정 |
| 결과를 받은 뒤의 다음 작업 | 악보를 확인·수정해 곡 작업에 쓰거나 다른 사람에게 공유 | 가정 |
| 현재 방식 | 녹음 후 오선지에 직접 옮겨 그림 (소요 시간: ○분, 확인 필요) | 가정 |

## 3. 제공 방식
- **기성 AI 도구 제외 이유:** 음성에서 음높이를 정확히 뽑는 처리를 맡길 수 없다 (가정, 확인 필요)

| 기준 | 후보 1: 메신저 봇 | 후보 2: 웹앱 |
|---|---|---|
| 사용자가 이미 쓰는 도구 안에서 끝나는가 | 폰 메신저에 음성 메시지를 보내면 끝난다 | 별도 주소로 접속해야 한다 |
| 사용자에게 새로 필요한 것 | 봇 친구 추가 | 회원가입 |
| 직접 제어할 수 없는 것 | 화면 (악보 수정 UI 불가) | 없음 |
| 첫 사용까지 걸리는 시간 | 짧음 | 길음 |

- **첫 제공 채널: 웹앱 (모바일 브라우저 대응)**
- **선택 이유:** 인식 결과를 사용자가 고치는 것이 핵심 흐름이라, 악보 수정 화면을 직접 만들 수 있는 채널이 필요하다. 메신저 봇은 수정 화면을 만들 수 없어 첫 버전부터 맞지 않는다.
- **추후 확장 아이디어:** 메신저로 녹음을 보내면 웹앱의 수정 링크가 돌아오는 입력 채널 추가

## 4. 동작 방식
- **사용자 입력:** 브라우저에서 바로 녹음 또는 음성 파일 업로드 (단선율 멜로디, 1분 이내)
- **AI 처리:** 음높이 인식 → 음 길이 분리 → 박자 보정
- **처리 방식:** 동기 처리. 1분 이내 녹음은 수십 초 안에 처리될 것으로 가정하고(측정 필요), 즉흥 메모라 바로 결과를 확인하는 맥락에 맞다. 긴 녹음을 지원하게 되면 비동기로 전환한다.
- **결과물 (출력 형식):** 화면에 악보 표시 → 조표·박자·템포 한 줄 → 불확실한 음은 표시 (감지된 음이 없으면 "감지된 음이 없어요") → 음 직접 수정 → MIDI 내보내기
- **사용자가 보는 순서:** 접속한다 → 녹음하거나 파일을 올린다 → "변환 중이에요" 안내를 본다 → 악보를 확인한다 → 틀린 음을 눌러 고친다 → MIDI로 내보낸다

## 5. 오류 대응
| 예상 오류 | 영향도 | 대응 장치 | 사용자에게 보이는 문구 |
|---|---|---|---|
| 잡음이 많거나 무음이라 음을 인식하지 못함 | 낮음 | 폴백 응답 | "음을 찾지 못했어요. 조용한 곳에서 다시 녹음해 주세요" |
| 화음·여러 악기가 섞여 엉뚱한 음으로 변환됨 | 중간 | 폴백 응답, 불확실 표시 | "멜로디 하나만 인식할 수 있어요. 불확실한 음은 ?로 표시했어요" |
| 음정·박자가 흔들려 음이나 박자가 틀림 | 중간 | 휴먼 인 더 루프(화면에서 직접 수정), 피드백 | "틀린 음이 있나요? 눌러서 고칠 수 있어요" |

## 6. 성공 기준
- 깨끗한 단선율 녹음 기준 음높이 정확도 90% 이상
- 음가 오차 한 단계 이내
- 1분 이내 음성이 1분 안에 처리됨
- 사용자가 고치는 음이 전체의 20% 이하
- 직접 오선지에 옮길 때보다 시간이 절반 이하로 듦
- 검증: 직접 채보한 정답 곡 10개 내외와 비교
